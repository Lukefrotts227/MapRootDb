MapRootDb

An experimental in-memory DAG relationship store with typed values, snapshots, and a loopback-only Rust TCP server.

What is this?

MapRootDb is a small relationship store written in Rust. Data is organized as a directed acyclic graph of Node objects held inside a Structure, giving each record explicit parent/child relationships rather than a flat table layout. The Database can hold multiple structures at once, and everything can be serialized to disk with bincode and reloaded later. A simple TCP protocol and server expose the database to trusted local clients on localhost. This is an alpha: its persistence and wire formats are deliberately not yet stable. It is intended for learning and non-critical local prototypes.

Build & install

git clone https://github.com/Lukefrotts227/MapRootDb
cd MapRootDb
cargo build --release
cargo run -- demo
cargo run -- serve

Requires a working Rust toolchain (cargo included).

The demo builds and queries a semi-strict graph, saves a snapshot, and exits. The serve command runs the localhost server; use cargo run -- --help for configuration.

In a second terminal, run the complete client walkthrough:

cargo run --example tcp_client -- 127.0.0.1:7878 tcp-client-demo.bin

This pings the server, creates and queries a graph, saves a snapshot, and shuts down cleanly.

Scope

MapRootDb stores keyed typed values and explicit parent/child relationships in directed acyclic graphs. It retrieves individual nodes or complete structures. It does not yet provide a query language, path/traversal queries, secondary indexes, transactions, or a production durability guarantee.

Security & limitations

The server enforces loopback-only binding. It has no authentication or encryption, and clients can request snapshot writes to paths visible to the server process. Do not expose it to untrusted clients.

Snapshots currently lack a magic header, format version, checksum, atomic replacement, and recovery log. The wire and snapshot formats are unstable. Connections use one thread each with 30-second read/write timeouts, and strong parent/child Rc links can retain connected nodes after a structure is dropped.

Recovery

--database PATH loads an existing snapshot and fails if it is missing or invalid; omit it to start empty. Occupied ports return an error, and non-loopback addresses are rejected. Ctrl+C and Command::Shutdown stop the server cleanly. See the repository README for verification commands and complete API notes.
